## Limits
- Only map literals with quoted keys are read. Keys built at run time (`{'a_$x': 1}`, spread `...map`, `toMap()` helpers) are invisible; dynamic keys seen in literals are counted but not named.
- The collection is guessed from the nearest `collection('x')` (or a getter / helper for it) before the write. Nested documents and batch writes through a stored reference can be attributed wrongly or skipped.
- A field counts as known when its name appears anywhere in `firestore.rules` (checks often sit in helper functions outside the collection block). A name the rules mention only for another collection is therefore not reported: that is a miss of this tool, and a stricter per-collection check gave mostly false alarms. Fields written only by functions (admin SDK) are not rule-checked at all.- A report line is a lead, not proof. The real proof is `docs/RULES_CONTRACT.md` (the app's own writes replayed against the rules) and `sh run-tests.sh`.
- Rules are never edited by this tool. A needed rules change goes to `docs/RULES_CHANGES_NEEDED.md` for the owner.
